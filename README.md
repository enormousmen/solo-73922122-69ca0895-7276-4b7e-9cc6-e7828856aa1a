# 单卷虚拟磁盘整理台（Flask）

虚拟磁盘回收逻辑块后，尾部的**空槽仍撑着镜像文件**。本项目提供一个 Flask
单卷整理页和一份带空槽的本地镜像，值班员可以：

- 按**逻辑块号**读取 4 KiB 数据；
- 一键启动**批量整理（compact）**，把在用块向镜像头部压紧并截短文件；
- 实时查看**实际文件长度**、槽位映射、整理游标、**最大提交批量**与
  **本轮实际执行的 fsync 次数**；
- 注入批前/批中/截短故障，观察“报错但数据仍可读、重试可续作”。

## 目录结构

```
app/
  disk.py      镜像格式、双份崩溃安全头、合批原地整理算法、读写锁
  seed.py      内置演示镜像（20 槽，14 个在用块 + 6 个空槽）
  web.py       Flask 应用与 HTTP API
  cli.py       命令行工具（seed/status/verify/compact-once/hard-exit/
               hard-exit-batch/resume）
  templates/index.html  单页界面
tests/         28 项单元/集成测试（含合批、枢轴周转、并发读、硬崩溃续作、
               批中崩溃原子性、撕裂头恢复、fsync/批量统计）
scripts/       可复现演示脚本（Docker 版 / 本地版 / 故障注入版）
Dockerfile, docker-compose.yml, requirements.txt
```

## 快速开始

### Docker Compose（推荐）

```bash
docker compose up --build
# 浏览器打开 http://localhost:8000
```

镜像文件放在命名卷 `disk-data` 的 `/data/disk.img`，容器重建不丢状态。
环境变量 `MOVE_DELAY`（秒）放慢每块搬移，便于观察整理过程。

### 本地直接运行

```bash
pip install -r requirements.txt
python -m app.seed data/disk.img     # 首次可省略，网页启动时会自动建
python -m app.web                    # 默认 0.0.0.0:8000，DISK_IMAGE/PORT 可覆盖
```

## 镜像格式

| 区域 | 偏移 | 内容 |
|---|---|---|
| 头副本 A | 0 | 4 KiB，世代号 + 状态机 + 槽表 + 游标/统计 + 整头 CRC32 |
| 头副本 B | 4096 | 同上，两份轮流写，永远至少一份完整有效 |
| 数据槽 0..N-1 | 8192 + i·4096 | 每个 4 KiB；槽表项 0=空槽，否则为“逻辑块号+1” |

内置镜像物理布局（`空`=空槽，数字=逻辑块号）：

```
[空, 空, 空, 空, 0, 1, 2, 3, 4, 空, 5, 6, 7, 8, 9, 10, 11, 12, 13, 空]
```

头部连续 4 个最终空槽使整理一上来就能合出 4 块一批的大批量。整理前文件
长度 `8192 + 20·4096 = 90112`；整理后恰好 `8192 + 14·4096 = 65536`，
逻辑块 0..13 顺序压紧到物理槽 0..13，**块号与逐字节内容均保持原样**。

## 批量整理算法如何满足各项约束

整理以**批**为最小单位，每批最多搬 `MAX_BATCH = 4` 块。规划器从游标 `i`
开始扫描：先越过已在正确槽位的块；随后把“目标块的最终槽 `i` 当前为空”
的直接搬移收集成一批，最多 4 块，遇到被占用的最终槽即停。

1. **合批 + 每批最多两次 fsync**
   一批的落盘顺序固定：
   1. 逐块 读源槽 → 一个复用的 4 KiB 暂存 → 写各自的**目标空槽**（不单独
      fsync）；整批数据写完后对镜像执行**第 1 次 fsync**；
   2. 把整批新槽表、游标、搬移/批量统计写进非活动头副本并 fsync
      （**第 2 次**），再切换活动头。
   因此任意一个搬移批对镜像恰好两次 fsync，进度随盘头一起提交。

2. **崩溃原子性：中途退出只见整批前或整批后**
   槽表只在整批数据 fsync 之后的盘头提交里更新。批处理途中进程被杀
   （SIGKILL）时，活动头仍描述批前布局；重开选取世代号最大的 CRC 有效
   头，看到的就是整批搬移前的完整布局，可原样继续。已提交的批则整体
   可见。`hard-exit-batch` CLI 与对应测试专门在“数据已 fsync、盘头未
   提交”的窗口硬退出来验证这一点。

3. **需要借空槽周转的布局也能整理**
   当最终槽 `i` 被别的在用块占着时，先把占槽块挪到一个 `≥ i` 的空枢轴
   槽（在用块数 U < 总槽数 S，区间内恒有空槽）。这次周转单独构成一个
   1 块批（同样最多 2 次 fsync），下一批目标块即可直接进入腾出的最终
   空槽。

4. **镜像外临时数据 ≤ 4 KiB**
   整批共用一个 `io.BytesIO` 暂存缓冲，逐块复用，任何时刻最多持有一个
   4 KiB 块（`max_temp_bytes` 可观测），不存在第二份临时块。

5. **读块不等整批写完，进度只记已提交搬移**
   槽表提交前读路径始终命中源槽旧数据；提交后目标槽已有完整数据。
   `pread` 在读写锁之外执行，整理的磁盘 I/O 不阻塞读。游标、搬移计数、
   最大批量只在盘头提交成功后推进，失败的批不留下任何进度。

6. **写盘出错就停下**
   批前故障在任何 I/O 之前抛出；批中数据写故障在槽表提交之前抛出，
   工作线程把状态置为持久化的 `error` 后停止，盘上仍是上一个已提交
   世代。界面再点“启动整理”从原游标续跑，统计（fsync 次数、最大批量）
   在 error→compacting 续作时保留，对 idle 卷发起新一轮时清零。

7. **截短安全**
   仅当全部在用块已压紧到前 U 个槽、并再次确认尾部槽表全为 0 后才
   `ftruncate`，不可能截到在用数据。

## 统计口径

- `max_batch_committed`：本轮已提交批中的最大块数（上限
  `max_batch_capacity = 4`）；
- `fsyncs`：进入 `compacting` 之后到回到 `idle` 之间对镜像实际执行的
  fsync 次数。每个搬移批固定 2 次，截短 1 次，截短后的 idle 盘头 1 次；
  进入整理态的那次状态提交发生在计数置位之前，不计入。演示镜像
  4 批（4+4+4+2）跑完为 `4×2 + 2 = 10` 次。
- `fsyncs_per_batch_capacity = 2`：每批连同进度更新的 fsync 上限。

## HTTP API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/` | 整理台页面 |
| GET | `/api/status` | 状态、文件长度、槽位图、游标、搬移/批量/fsync 统计、临时峰值 |
| GET | `/api/blocks/<lbn>` | 按逻辑块号读 4 KiB（返回前 64 字节 hex 与可打印预览） |
| POST | `/api/compact/start` | 启动整理；error 态调用即续作 |
| POST | `/api/fault/move` | 一次性注入：下一批在任何 I/O 前抛错 |
| POST | `/api/fault/data-write?at=N` | 一次性注入：下一批第 N 次数据写抛错（槽表不提交） |
| POST | `/api/fault/truncate` | 一次性注入：下一次截短抛错 |
| POST | `/api/reseed` | 重建出厂演示镜像（仅非整理中） |

## 可复现的中断续作示例

```bash
# Docker：真实 SIGKILL 强杀容器，重启后自动续作并校验长度与块内容
bash scripts/demo_interrupt_resume.sh

# 无 Docker：子进程 os._exit(42) 硬退出模拟 SIGKILL（不执行任何清理），
# 两次中断后续跑，最后 verify 全部块
bash scripts/demo_local.sh

# 故障注入（需要先启动网页）：批中数据写故障 + 截短故障
bash scripts/demo_fault_injection.sh

# 批中崩溃原子性：在“数据已 fsync、盘头未提交”窗口硬退出
python -m app.cli hard-exit-batch data/disk.img
python -m app.cli resume data/disk.img
```

> 说明：本项目开发所在的沙箱禁止向进程发送信号，自动化测试里用
> `os._exit` 模拟硬崩溃（语义等价：无 finally、无缓冲刷新、无 fd 清理，
> 恢复只依赖已 fsync 的盘上状态）；Docker 演示脚本使用真实的
> `docker kill --signal=KILL`。

## 已知边界

- 槽表为定长（单卷上限约 1000 个槽，见 `disk.py` 的 `SLOTS_MAX`）；
- 单工作线程模型：同一时刻只跑一个整理任务，重复启动返回 409；
- 暂存缓冲在内存中（`io.BytesIO`），容量恒 ≤ 4 KiB；若要求暂存也落盘，
  可替换为同目录下的单块临时文件，算法不变；
- 头结构版本为 `HDR_VERSION=2`，与旧版（v1）镜像不兼容，重建镜像即可。
